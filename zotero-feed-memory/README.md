# Journal RSS Memory

用于 Zotero 9.0.x 的本机辅助插件。需要已安装并配置好 Translate for Zotero；不需要把翻译密钥放进 GitHub。

## 安装与启用

1. 在 Zotero 的“工具 → 插件”中，点击齿轮，选择“从文件安装插件”，选择 `dist/journal-rss-memory-0.1.0.xpi`。
2. 打开“工具 → RSS 记忆 → 启用自动翻译、缓存和已读归档”。初次安装默认暂停，启用后会逐批处理已订阅的条目；翻译使用现有插件中选定的服务，可能产生该服务的费用。
3. 在条目列表的列标题上右键，勾选“RSS 来源标记”和 Translate for Zotero 提供的“标题翻译”。原文标题不会被改写。

## 重复标记

- `曾见官方（标识一致）`：同一 DOI、PII、文章链接等标识在官方 RSS 中出现过。
- `官方同题（待核对）`：题目一致，但缺少共享的可靠标识；不会仅凭同题合并已读状态。
- 空白不代表文章独有，也可能是官方源不可访问、尚未对照或缺少匹配信息。

插件对照已经订阅的官方源。对本项目的八种 ScienceDirect 期刊，还会最多每六小时尝试一次官方 RSS 对照；不将它们自动添加为额外订阅。IJDE、IEEE、中文期刊需要已订阅相应官方 RSS 才能做本地对照。

标记记录“曾经核实的重合”，不是“目前官方源仍然包含该文”。官方 RSS 删除历史条目或临时不可访问，不会把曾经确认的重复状态抹掉。

## 译文缓存

缓存按原文标题和目标语言区分，不依赖 Zotero 的临时条目 ID。刷新、重新出现的文章会优先恢复译文；标题变更或目标语言变更需要新的翻译。成功结果才缓存，失败后延迟重试。已有译文会按其记录的语言缓存；旧译文没有语言信息时，按当前目标语言接收。

自动处理所有订阅中的普通条目，采用串行批次，每批最多 20 个候选标题，请求之间间隔 1.5 秒，完成一批后还会等待下一轮。不会同时发出大量请求。网络超时后，在原请求结束前暂停发送，避免后台累积请求。第一次处理很多条目可能需要较长时间。中译中的标题会跳过。

英文 RSS 原先误标为 `zh-CN`，本次生成器已改为 `en`。Zotero 会将频道语言继承给条目，而原翻译插件可按语言跳过中文，所以错误语言标签会影响手动翻译。自动缓存插件通过原翻译插件的文本 API 翻译，不依赖 DOI 网页抓取。

## 已读归档

启用后，订阅区会新增 `RSS 已读归档（本机）`。已读时记录轻量历史和归档条目；超过原订阅的“已读保留天数”（未设置时按 30 天），先确认磁盘记录与归档条目已存在，再移除原订阅中的条目。只保留标题、链接、DOI、日期、译文及来源，不复制 PDF、附件或全文。

源 RSS 再次提供旧文时，插件根据保留的标识恢复已读状态并再次归档，不让它长期滞留原列表。由于处理发生在 Zotero 接收更新之后，刷新时可能短暂显示重返的条目。条目的全部标识均发生改变且没有可关联的 DOI/PII/URL 时，无法保证自动认出它。

选中归档条目，再点“工具 → RSS 记忆 → 将所选归档放回原订阅的未读列表”，可以重新阅读。原订阅已取消时，先重新添加；插件不会擅自重建外部订阅。在原订阅中手动标未读，也会更新记忆。

Zotero 原生的过期清理通常还要求条目已经不在源 RSS 中。本插件保留独立记忆，因此可以在源长期保留旧文章的情况下清理原列表。归档有独立 GUID，不会与来源条目占用同一个 Zotero Feed GUID。

## 隐私、备份与停用

缓存位于 Zotero 数据目录下的 `journal-rss-memory/state.json`，通过“状态与缓存位置”查看。它含个人阅读记录，**不要上传到公开仓库**。备份时同时保留这个目录。文件损坏时停止自动处理，不用空文件覆盖原记录。

归档使用带随机路径的本机地址 `127.0.0.1`，不是 GitHub Pages 公共 RSS。数据只保存在当前电脑；Zotero 同步可能同步订阅的地址，但不会同步这个插件的本地缓存。在另一台电脑上不会凭空恢复个人已读记录。

在“工具 → RSS 记忆”中可以暂停。停用插件不会删除已有缓存或归档；但缓存恢复和自动归档会停止，源站后续仍可能重新提供旧文章。切勿将“删除全部本地历史”和“永久记住所有已读文章”视为能同时满足的要求：至少必须保留轻量标识。

## 构建与验证

```powershell
node --test zotero-feed-memory/test-core.cjs
python -m unittest discover -s tests -v
python zotero-feed-memory/build.py
```

打包白名单只有 `manifest.json`、`bootstrap.js`、`core.js`、`addon.js`。测试目录、个人缓存及翻译密钥不会进入安装包。

`smoke-setup.py` 和 `smoke-debug-install.py` 用于隔离 Zotero 数据目录中的集成验证。测试使用模拟翻译服务，不消耗真实服务额度，也不验证第三方服务可用性。插件不会自动安装到日常使用的 Zotero 配置中。
